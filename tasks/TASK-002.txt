## Objective

Create an independently tested CommonJS module that validates explicit loan-policy parameters
and creates detached, recursively frozen copies of valid policies. This is a foundation for
future administrator configuration and per-loan terms preservation, NOT a live behavior change.

store ambiguous interest/months values and overwrite the same database row when edited. The existing
installment generator interprets interest as annual, uses equal principal with declining-balance

An explicit, unit-safe contract is a small prerequisite for reliable configuration and snapshots.
No final lending policy, legal exemption, store approval, or financial formula is being approved here.

## Required Changes

1. Export exactly these synchronous functions from backend/services/loanPolicy.js:

   validateLoanPolicy(input)
   createLoanPolicySnapshot(input)

   The module must have no imports, I/O, logging, environment reads, clock reads, randomness,
   timers, global mutation, DB connection or application dependencies. No external packages.

2. Implement this exact version-1 data shape. ALL listed fields are required; no defaults,
   aliases, coercion, trimming or extra keys at any object level. Example TEST FIXTURE only:

   {
     schemaVersion: 1,
     policyId: "fixture-monthly",
     policyVersion: 1,
     currency: "DOP",
     amount: { minMinor: 1000000, maxMinor: 2000000 },
     interest: {
       rateBps: 1800,
       period: "monthly",
       method: "equal_principal_declining_balance"
     },
     repayment: { installmentCount: 2, intervalDays: 30 }
   }

   Units and constraints:
   - schemaVersion: number exactly 1; reject unsupported versions.
   - policyId: string matching /^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$/.
   - policyVersion: positive safe integer supplied by the caller. Do not allocate versions,
     check uniqueness or infer persistence. This is distinct from schemaVersion.
   - currency: exactly "DOP".
   - amount.minMinor and maxMinor: positive safe integers in DOP cents; minMinor <= maxMinor.
     Equal bounds are valid. 1000000 cents means RD$10,000. Do not convert existing DB fields.
   - interest.rateBps: nonnegative safe integer, including zero. One basis point = 0.01 percentage
     point; 1800 means 18 percent for the EXPLICIT period. Do not divide/multiply the rate.
     No business/legal maximum is invented in this structural validator.
   - interest.period: exactly "monthly" or "annual"; it is the RATE period, not the payment interval.
   - interest.method: exactly "equal_principal_declining_balance". This is metadata identifying
     the current backend calculation family; this task does not calculate, verify or activate it.
     Reject other method names and formula strings. Do not implement hypothetical calculators.
   - repayment.installmentCount and intervalDays: positive safe integers. The interval is explicit
     fixed days, NOT calendar months. No upper business limit is invented. No schedules are allocated.
   - All object nodes must be ordinary plain objects with Object.prototype or a null prototype.
     Reject null, arrays, Dates and other non-plain objects in those positions.
   - Reject numeric strings, booleans and boxed numbers for numeric fields; reject NaN, infinities,
     fractional integers and numbers outside Number.isSafeInteger's range.

   This input is an internal JSON-like data contract, not an HTTP/DB adapter. Handling hostile
   proxies/accessors and arbitrary cyclic JavaScript graphs is outside scope. Do not add an
   extensible expression language, generic schema framework or permissive extensions object.

3. validateLoanPolicy must not mutate or freeze input. Return exactly:
   - valid: { valid: true, errors: [] }
   - invalid: { valid: false, errors: [{ path, code }, ...] }

   Validation errors have exactly path and code, never submitted values or serialized input.
   Paths: "$" for a bad root; otherwise dotted names, e.g. "interest.period".
   Codes:
   - REQUIRED: known field absent or explicitly undefined.
   - INVALID_TYPE: wrong primitive type or object shape (including null).
   - INVALID_VALUE: right primitive type, wrong value/range/enum/integer constraint.
   - UNKNOWN_FIELD: an extra own enumerable string key; include its dotted path, not its value.
   Check object type before descending; a missing/invalid parent yields one parent error and
   no child errors. For inverted valid amount bounds, use amount.maxMinor / INVALID_VALUE.
   Collect independent errors without duplicates; sort by path then code using ordinary string
   comparison for deterministic results. Invalid ordinary data must return errors, not throw.

4. createLoanPolicySnapshot must validate using the same rules. If invalid, throw a TypeError
   with message "Invalid loan policy", code "INVALID_LOAN_POLICY" and an errors property equal
   in content to validateLoanPolicy(input).errors. Do not expose raw input in the error.

   If valid, return an owned ordinary JSON-compatible object with exactly the accepted fields.
   Copy all nested objects and recursively Object.freeze the output, without freezing input.
   Preserve units, numeric values, ID and versions exactly. Repeated calls are deterministic
   in content but produce independent objects. No timestamps, hashes or generated identifiers.

   Document briefly in code comments: freezing is in-process protection, not immutable database
   storage, a signed contract, legal validation, or configuration activation. Snapshotting this
   financial subset does not yet capture all future loan conditions, fees or rank benefits.

5. Add isolated tests using only node:test, node:assert/strict and this new module (Node built-ins
   may also be used for an isolated import check). Do NOT import existing DB-connected models,
   controllers, index.js, dotenv or integrations. No application route imports the new module yet.

Database/testing scope: pure unit tests and the existing mocked backend regression suite only.
