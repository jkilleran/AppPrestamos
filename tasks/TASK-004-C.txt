## Required Changes

1. C1 — After the existing admin guard, accept an update/delete ID only when it is a positive safe integer number or a digits-only string that normalizes to one. Reject zero, negatives, decimals, blanks, signs, exponent/hex notation, trailing characters, arrays, objects, booleans, unsafe integers, and missing IDs with 400 exactly `{ "error": "Datos inválidos" }` and zero model calls.
2. C2 — Pass the normalized numeric ID to the model.
3. C3 — Preserve TASK-004-A payload validation. For update, invalid ID must not reach persistence; do not relax any A validation rule.
4. C4 — Make model deletion use `DELETE ... WHERE id=$1 RETURNING id` (or equivalent single-query evidence). If update/delete finds no row, respond 404 exactly `{ "error": "Opción no encontrada" }`.
5. C5 — Catch create/update/delete persistence errors and return 500 exactly `{ "error": "Error interno" }`; never include exception/SQL details.
6. C6 — Preserve authorization precedence: missing/non-admin user still receives the existing 403 before identifier, payload, or persistence processing.
7. C7 — Preserve successful create 201, successful update 200 with updated object, and successful delete 200 `{ "success": true }`.
